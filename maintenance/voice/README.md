# 语音转写与按 ID 修复

正式自动稿只来自腾讯云 `SentenceRecognition/16k_zh`，`FilterPunc=0`，文字、断句和标点全部采用腾讯原始 `Result`。不再运行 Whisper 或二次标点模型。

保留的链路：

- `tencent_asr.py`：识别新语音并保留音频指纹。
- `adopt_tencent.py`：将腾讯结果升级为正式自动稿；人工决定永远优先。
- `app_review.py`：按消息 ID 读取现有文字、腾讯候选及音频指纹，提交人工修正或舍弃。
- `playback.py`、`codec.py`、`silk.py`：安全定位、解码和播放 QQ SILK 原音。
- `review.py`：事务化写入人工确认/排除和审计记录，拒绝原音、文字或候选已变化的过期提交。

自动转写由“一键构建新版 APK”触发，不要求维护者完成风险复核队列。旧风险打分、随机抽样、盲听质量报表和常驻状态服务已移除；它们不参与现在的维护链路。

规则：

1. 自动稿可供 Agent 检索，但必须携带 `voice_transcript/automatic_asr` 来源标签。
2. 听不清就排除，禁止根据上下文猜写。
3. 按消息 ID 可以重新打开任何语音进行修正。
4. 保存人工决定前必须播放原音，并再次核对文字和音频 SHA-256。
5. 原始 QQ 音频、旧文字和审计记录不因排除而删除。

## 修正步骤

1. 打开 PC 维护工具的“按 ID 修复语音”。
2. 输入消息 ID，确认显示的北京时间、说话人和当前文字。
3. 播放并完整听完原音；内容清楚时修正文字，听不清时选择舍弃。
4. 勾选实际听音确认，再保存。过期的原音或文字会拒绝提交，需要重新打开。
5. 下一次构建 APK 时，修正后的内容才进入手机；原本已保存的回答不会自动重写。

听音确认只记录维护者的明确操作，程序无法证明人是否真正听完。看着候选编辑的结果也不应宣称为独立语音准确率。
