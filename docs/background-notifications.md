# Android 后台与通知

这两种通知都是 Android 本机能力，不需要 7u 服务器。

## 后台回答

应用级 `ConversationController` 拥有会话和请求；Android Application 保留同一个 FlutterEngine，页面或 Activity 销毁不会主动销毁该引擎。

发送时先在前台启动 `dataSync` 服务保护，再保存 pending，之后才调用模型。服务展示低优先级通用运行通知，并持有有限唤醒锁。回答/错误保存成功后才发送完成/失败通知；只在 App 不在前台时发送，内容不包含问题或答案正文，点击进入原会话。

任务按独立 ID 管理。多会话同时运行时，结束一题不停止其他题；删除会话取消对应请求，不复活已删除会话。最后一个任务结束释放资源、停止服务。服务自身连续运行保护上限为 2 小时，并处理 Android 系统超时；这不是回答耗时承诺。

相关实现：

- `app/lib/core/conversation_controller.dart`：状态、存盘、取消和导航。
- `app/lib/core/background_answers.dart`：只传任务/会话 ID 和结果状态的通道。
- `app/android/app/src/main/kotlin/com/sevenu/app/` 下的 `SevenUApplication`、`BackgroundAnswerBridge`、`AnswerForegroundService`：引擎、服务、权限与通知。

## 每日短句

默认每天北京时间 12:00 提醒，不随手机时区改变。方向在小问题、陈述、回忆之间随机，再从该方向未发过的内容中选取；该方向耗尽才循环。有限池不是无限新内容。

内容来自 APK 的 `assets/memory/daily_memories.json`。PC 构建阶段生成并审核，手机闹钟触发时不联网、不调用模型、不创建 FlutterEngine，也不启动回答前台服务。

默认锁屏直接显示短句。顶部铃铛可更改时间、关闭每日提醒、隐藏锁屏预览或打开系统通知设置。点击通知显示对应日期、人物和逐字原话；“接着聊聊”只填入新会话草稿，仍需用户发送。

原生 `DailyMemoryScheduler` / `DailyMemoryReceiver` 负责调度、选取与同日去重；Flutter `daily_memories.dart` 和 `daily_memory_notifications.dart` 负责设置与详情。通知入口只携带 ID，再从本地资产查原文，不信任外部 Intent 的正文。

## 权限与隐私

- Android 通知权限被拒绝或通知分类关闭，不取消正在生成的回答；答案仍保存，只是收不到对应通知。
- 回答完成通知使用通用文字；每日提醒的锁屏内容由用户设置。
- 权限请求不是后台任务启动的前置等待条件，拒绝后不会每题反复弹窗。
- 使用不精确本地闹钟，不申请精确闹钟或忽略省电权限，不自动改变系统省电设置。
- 开机、覆盖升级和时钟变化会重新安排每日提醒，不重放模型请求。

## 能保证什么

普通 HOME、锁屏和 Activity 回收情况下，前台服务可继续已开始的任务。系统强停、活跃应用停止、厂商冻结或进程被终止仍可能中断；应用不能保证绕过这些限制。

中断后保留已经存下的未完成问题，重开由用户决定是否重试，不自动重新付费。如果答案尚未成功落盘，完全终止进程可能丢失内存结果；因此界面会给重试保存入口，不发误导的成功通知。

每日提醒不是精确计时器，省电或系统批处理可能延迟，不承诺 12:00:00 准点。每个北京时间日期最多一次；不补发错过的日子。去重状态先保存，再发通知，极小的崩溃窗口可能漏发一次，但不会因重启重复推送。强行停止后通常需要重新打开应用才能恢复调度。

## 验证重点

在独立测试环境验证发送后 HOME/锁屏/销毁 Activity、多个任务、删除会话、拒绝权限、成功/错误持久化、冷/热通知点击和资源释放。每日部分验证时间、锁屏预览、关闭、改时刻、同日不重复、升级/重启重排，以及无应用进程时的闹钟投递。

旧安装包的实测只证明当时产物，不替代本轮修改后的验收。构建与发送前按 [发布手册](android-release.md) 核验新包。
