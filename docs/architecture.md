# 架构

## 两个运行环境

手机负责阅读、检索和连续问答；PC 负责准备可信资料和构建安装包。两者不通过 7u 服务器同步。

```text
PC QQ → 增量工作库 → 自动转写 / 人工修正 → 净化记忆包 ┐
                   → 每日短句生成 + 独立审核          ├→ 签名 APK
agent/prompt.md → 提示词副本                           ┘

App 页面 → 应用级会话控制器 → 问答引擎 → 本地检索 / 模型请求
                    └→ 本机会话存储、Android 后台保护和通知
```

PC 工作库不直接打包。原音、原始导出、密钥、人工操作审计和生成过程输入输出不进入 APK。包内只有经过准入的文字/语音稿、必要引用关联、覆盖统计、档案和最终短句等运行资产。

## 代码边界

| 位置 | 负责 | 不负责 |
| --- | --- | --- |
| `app/lib/screens/`、`widgets/` | 展示、编辑草稿、用户操作 | 直接发模型请求或写聊天工作库 |
| `app/lib/core/conversation_controller.dart` | 会话状态、并发任务、生命周期、存盘顺序、通知导航 | 检索策略、提示词文风 |
| `conversations.dart`、`local_store.dart`、`question_history.dart` | 手机存储与答案/引用数据 | 修改随包记忆库 |
| `api.dart`、`question_agent.dart` | 问答入口、上下文、工具循环、证据校验 | QQ 提取、语音转写 |
| `memory_pack.dart`、`model_client.dart` | 只读检索、模型通信 | UI 状态、第二套会话历史 |
| `app/android/` | 缓存引擎、前台服务、权限、通知与闹钟 | 第二套模型编排、服务器 |
| `maintenance/build.py`、`sync.py`、`release.py` | 完整 PC 构建链、阶段检查、正式发布 | 手机在线后台 |
| `maintenance/ingest/`、`voice/` | 增量资料、语音处理与人工审计 | 自动假定人工已经听审 |
| `maintenance/archive/`、`core/` | 档案/人物权威映射、隐私和共享规则 | App 页面 |
| `maintenance/archive/memory_pack.py`、`maintenance/daily_memories.py` | 生成随包资产 | 手机每天重新请求模型 |
| `tools/qa/` | 显式回归、模型诊断和发布审计 | 普通维护入口 |

`maintenance/model_client.py` 供 PC 短句生成/审核使用，不是手机自由问答的另一套实现。`agent/` 仅保留主提示词与说明。第三方解析器隔离在 `third_party/qq_parser/msgdb/`，不与业务规则混放。

PC 根路径统一在 `maintenance/paths.py`；公开配置模板与本机覆盖由 `maintenance/config.py` 合并。生产模块不反向导入 `tools/` 或 `tests/`，测试会检查此依赖边界。模型与腾讯的加密配置共用 DPAPI 基础函数，但保留独立格式和熵值。Python 使用锁定依赖与 Ruff 格式/静态检查，不维护旧路径兼容层。

## 人物视角：只转换一次

| 环境 | self | partner |
| --- | --- | --- |
| PC 原工作库、`config/local.json`、语音维护窗口 | 维护人 / 赠送者 | 收礼人 |
| 导出的 App 记忆包、模型工具结果 | 收礼人，即“她”，正文称“你” | 赠送者，即“我”，正文通常称“TA” |

PC 配置中的 `self_qq` 对应维护人，`partner_qq` 对应收礼人。导出时交换一次；App 检索、引用和生成不再交换。说话人与事实描述对象是两回事，不能用引文说话人直接替代画像事实的主体。

模型结合完整问题决定问谁、检索谁；程序不按“他/我”等单个代词硬判目标。程序核对引用消息 ID、逐字原文和 speaker；正文代词、情感推断、错会意仍需质量评测，不能由引文校验完全保证。

## 连续问答

每个会话独立保存完整对话、草稿和未完成问题。发送时先启动 Android 后台保护、保存 pending，再调用模型；保存失败不会付费生成。答案保存成功后才发完成通知。保存失败可重试保存现有结果，不必重问。

模型只接收当前会话保留的完整轮次；过长历史优先保留近期内容。历史答案不是 QQ 原话，历史引用必须在当前记忆包重新核验。用户补充只影响该会话，不自动写回 PC 档案。

每轮首问和追问重新获得独立技术预算：最多 12 次模型调用、8 轮检索、32 次工具调用和 24 万字符工具内容。模型自主决定关键词、人物、时间、数量、游标、上下文范围和停止时机；预算是防失控上限，不是用户额度。

可调用的本地能力包括文本检索、附近语境、引用关联、人物档案及分组计数。参数错误可反馈给模型修正；本地文件/数据库故障与模型服务错误不会伪装成“没有记录”的成功答案。失败保留问题供用户重试。

## 存储与更新

手机的会话库与只读记忆包分离。APK 覆盖升级替换资料，不清空会话；旧回答及其生成版本保留。PC 修正、换 Key、改提示词和换短句池均需生成并安装新版，没有热更新。

`maintenance.build` 持同一进程锁覆盖导入到发布。同步内部仍持导入锁；内部函数接收已持锁状态，避免重入死锁。失败保留已完成导入/转写及备份，不发布半成品、不覆盖历史 APK。

开发合成资产带 `is_synthetic` 标记，只用于干净克隆的测试和调试；不得作为生产资料或正式发布产物。
